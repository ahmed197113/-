# جمعيتي — تطبيق تنظيم الجمعيات (الادخار الدوري)

تطبيق ويب تقدمي (PWA) عربي بالكامل لإدارة "الجمعية": مجموعة يدفع كل عضو فيها قسطاً ثابتاً كل دورة، ويستلم أحدهم المبلغ كاملاً بالترتيب حتى يستلم الجميع.

> **المبدأ:** التطبيق أداة تنظيم وتوثيق فقط. لا يحتفظ بالأموال ولا يحوّلها، والدفع بين الأعضاء مباشرة. لا فوائد ولا رسوم.

**أسماء بديلة مقترحة:** "دوري"، "قَطّة"، "سهمي"، "جمعة خير".

## 📱 التثبيت على الجوال (APK)

1. حمّل الملف [`release/jamiyati.apk`](release/jamiyati.apk) على جوال أندرويد (7.0 فأحدث).
2. افتحه من "التنزيلات". إن ظهر تنبيه "تثبيت تطبيقات غير معروفة" فاسمح للمتصفح أو مدير الملفات بالتثبيت.
3. افتح **جمعيتي** وأدخل اسمك ورقم جوالك، أو جرّب البيانات التجريبية أولاً.

**ما يضيفه تطبيق أندرويد على نسخة الويب:**
- يعمل دون إنترنت بالكامل: الواجهة والخط العربي مضمّنان في التطبيق.
- تذكيرات تصل والتطبيق مغلق: قبل القسط بـ3 أيام، ويوم الاستحقاق، وبعد التأخير، ويوم دورك. وللمنظِّم ملخص قبل كل دورة. تُعاد جدولتها تلقائياً بعد إعادة تشغيل الجوال.
- القفل ببصمة الإصبع أو الوجه (أندرويد 9 فأحدث)، أو برمز.
- حفظ الإيصالات والتقارير وملفات CSV والنسخ الاحتياطية في مجلد "التنزيلات/Jamiyati" مع قائمة المشاركة (واتساب وغيره).
- حفظ التقرير والإيصال PDF عبر خدمة الطباعة في أندرويد.
- اختيار صورة الإثبات من المعرض.
- روابط واتساب تُفتح مباشرة في تطبيق واتساب.
- نسخ احتياطي تلقائي لبيانات التطبيق ضمن نسخ جوجل الاحتياطية (allowBackup).

> **مهم:** البيانات محفوظة على جوالك فقط، ولا خادم في هذه النسخة. من **حسابي ← نسخة احتياطية** احفظ نسخة شهرياً وأرسلها لنفسك، لتستعيدها على جوال جديد.

## 1) الخطة

### التقنية المختارة ولماذا

| الطبقة | الاختيار | السبب |
|---|---|---|
| الواجهة | React 19 + TypeScript + Vite | سريع وخفيف (~140KB مضغوط)، ويعمل كـ PWA قابل للتثبيت على أندرويد وiOS دون متجر |
| التخزين الحالي | محلي أولاً (localStorage) خلف طبقة `store/` | يعمل فوراً ودون اتصال، ويسمح بتجربة كاملة بلا خادم |
| الإنتاج | Supabase (Postgres + Auth بالجوال OTP + Storage + Edge Functions) | علاقات واضحة بين الجداول تناسب البيانات المالية، وRLS للخصوصية، وtriggers لمنع حذف الدفعات وحماية السجل. المخطط جاهز في `supabase/schema.sql` |
| الحسابات | دوال نقية في `src/domain/calc.ts` | منفصلة عن الواجهة ومختبرة بالكامل (Vitest) |
| المكتبات | `qrcode` فقط | الإيصالات (Canvas)، وPDF (طباعة المتصفح، تدعم العربية بالكامل)، وCSV والأيقونات كلها بلا مكتبات |

### نموذج البيانات

```
Users ─┬─< Circles (organizer_id)
       └─< Members (user_id، فارغ لمن لا يملك التطبيق) >── Circles
Circles ─< Shares (position = ترتيب الاستلام) ─< ShareHolders (member_id, fraction 1 | 0.5)
Circles ─< Postponements (before_cycle)          ← الدورات (Cycles) تُشتق: start + frequency + التأجيلات
Circles ─< Payments (member_id, cycle_index, status: pending|confirmed|rejected|voided, proof)
Circles ─< Payouts  (share_id, member_id, cycle_index, recipient_confirmed_at)
Circles ─< SwapRequests (from_share, to_share, موافقات: الطالب/الطرف الآخر/المنظم)
Circles ─< ActivityLog (إضافة فقط، prev_hash → hash)
Users   ─< Notifications (key فريد لمنع تكرار التذكير)
Members.replaces_member_id → Members  (البديل يرث الأسهم والدفعات)
```

- **السهم** وحدة الاستلام. صاحب السهمين له صفّان في Shares. **نصف السهم** سهم واحد له حاملان بكسر 0.5.
- **الدورات** لا تُخزن بل تُحسب من تاريخ البداية والدورية والتأجيلات. هذا يضمن أن تأجيل دورة يعيد حساب كل التواريخ بلا تضارب.
- الأنواع في `src/domain/types.ts`، ومخطط الإنتاج مع RLS والـ triggers في `supabase/schema.sql`.

### مراحل البناء

1. **المرحلة الأولى (MVP):** ✅ إنشاء الجمعية، والأعضاء، والترتيب والقرعة، وشبكة الدفعات، والتذكير عبر واتساب، ولوحة المستخدم.
2. **المرحلة الثانية:** ✅ الحالات الخاصة، وسجل الالتزام، والإيصالات والتقارير، والتصدير.
3. **المرحلة الثالثة (الإنتاج):** ربط Supabase، وOTP حقيقي، وWeb Push من الخادم، وإرسال واتساب تلقائي، والدفع للاشتراك المميز. انظر "ما تبقى".

## 2) التشغيل والبناء

```bash
cd jamiyati
npm install
npm run dev        # http://localhost:5173
npm test           # 47 اختباراً لمنطق الحسابات والعمليات
npm run build      # فحص الأنواع + بناء dist/
npm run preview    # معاينة نسخة الإنتاج (مع Service Worker)
npm run apk        # بناء APK موقّع → release/jamiyati.apk
```

### بناء الـ APK

`android/build.sh` يبني التطبيق دون Android Studio أو Gradle:

1. يبني الواجهة.
2. يضعها في `assets/www`.
3. يجمّع الموارد بـ `aapt2`.
4. يجمّع كود Java (WebView أصلي) ويحوّله إلى `classes.dex`.
5. يحاذي الملف ويوقّعه بمخطط v2 عبر مكتبة `apksig` من Google، ثم يتحقق من التوقيع.

ينزّل أدواته تلقائياً مرة واحدة من npm وMaven Central وGitHub. يحتاج: Node 20+، وJDK 17+، وPython 3، و`zip`، و`curl`.

**مفتاح التوقيع:** يُنشأ تلقائياً في `~/.jamiyati/release.p12`، أو في المسار المحدد في `JAMIYATI_KEYSTORE`، وكلمة مروره في ملف `.pass` المجاور.
- احتفظ بالمفتاح خارج المستودع.
- كل تحديث لاحق يجب أن يُوقَّع بالمفتاح نفسه، وإلا يرفض الجوال التحديث فوق النسخة المثبتة.
- إن رفضه، فلا تحذف التطبيق قبل أخذ نسخة احتياطية.

**كود أندرويد** في `android/src/app/jamiyati/`:
- `MainActivity`: تخدم الواجهة من أصل `https://app.jamiyati.local` الآمن، وتوفّر جسر `window.JamiyatiNative`.
- `Reminders` و`ReminderReceiver`: التذكيرات المجدولة.

**الجانب المقابل في الويب** `src/lib/native.ts`. كل دالة فيه لها بديل قياسي في المتصفح، فالكود نفسه يعمل كـ PWA وكـ APK.

لتجربة سريعة اختر **"جرّب ببيانات تجريبية"**، فتدخل باسم "أحمد"، المنظِّم. البيانات نسبية لتاريخ اليوم:

- **جمعية الأصدقاء:** 10 أعضاء، وقسط 1000 ر.س شهرياً، وبدأت قبل 3 أشهر.
  - خالد متأخر في الدورة 3 (دفع 300 جزئياً).
  - إثباتا دفع بانتظار التأكيد (مريم، وعمر بدفعة جزئية).
  - طلب تبديل من عمر مع مريم: وافقت مريم وينتظر موافقة المنظِّم.
  - يوسف مساعد للمنظِّم، وخالد وليلى بلا تطبيق.
  - القرعة حقيقية وقابلة للتحقق بالبذرة 482913.
- **جمعية العائلة:** أسبوعية، وأحمد عضو فيها بنصف سهم مع أخيه سعد.
- **جمعية الزملاء 2025:** مكتملة، وتغذي سجل الالتزام والشارات.

الدخول بالاسم ورقم الجوال مباشرة، لأن البيانات على الجهاز فقط. رمز OTP جاهز في الكود، ويُفعَّل بـ `REQUIRE_OTP` عند ربط خادم.

كل المزايا مفعلة في هذه النسخة. حدود الخطة المجانية (نموذج الربح) موجودة في الكود، ومختبرة، وتُفعَّل من الإعدادات.

## 3) النشر

- **استضافة ثابتة** (Netlify أو Vercel أو Cloudflare Pages أو GitHub Pages): ارفع مجلد `dist/` بعد `npm run build`. المسارات تستخدم `#/` فلا يلزم إعداد إعادة توجيه، و`base: './'` يسمح بالنشر في مجلد فرعي. يلزم HTTPS للـ PWA والبصمة والإشعارات.
- **الإنتاج مع Supabase:**
  1. أنشئ مشروعاً وشغّل `supabase/schema.sql`.
  2. فعّل Phone Auth (Twilio أو MessageBird).
  3. أنشئ Storage bucket خاصاً باسم `proofs`.
  4. ضع `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` في `.env`.
  5. استبدل `LocalDemoAuth` في `src/lib/auth.ts`. التعليمات موجودة في الملف.
  6. استبدل تنفيذ `mutate()` و`actions.ts` باستدعاءات Supabase. واجهات الدوال تبقى كما هي.
  7. انقل `runReminders` إلى Edge Function مجدولة (cron يومي) ترسل Web Push. معالج `push` جاهز في `public/sw.js`.

## 4) الاختبارات

`src/domain/calc.test.ts` (30 اختباراً) و`src/store/actions.test.ts` (17 اختباراً):

- **التواريخ:** القص لنهاية الشهر بلا تراكم، والسنة الكبيسة، والأسبوعي، والنصف شهري، والدورة الحالية، ومهلة السماح.
- **نصف السهم:** القسط والاستلام المقسومان، وأن ما يُدفع يساوي ما يُستلم، والتحقق من اكتمال الأسهم.
- **الانسحاب:** قبل الاستلام (رد الدفعات واستبدال يرث الدور والدفعات)، وبعده (التزام بالباقي ومنع الاستبدال).
- **التأجيل:** إزاحة الدورة وما بعدها، وتراكم التأجيلات، ومنع تأجيل دورة حلّ موعدها.
- **أخرى:**
  - حالات الشبكة والدفع الجزئي.
  - استبعاد الدفعات المرفوضة والملغاة.
  - التسوية النهائية المتوازنة.
  - سجل الالتزام والشارات.
  - القرعة بالبذرة وأولوية الطلب.
  - حاسبة الملاءمة والتذكيرات.
  - الصلاحيات.
  - حدود الخطة المجانية.
  - اكتشاف أي عبث في سلسلة السجل.
