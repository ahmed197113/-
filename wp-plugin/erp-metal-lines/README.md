# إضافة WordPress: نظام المحاسبة والمقاولات — الخطوط المعدنية

نقل حرفي لبرنامج المحاسبة والمقاولات المكتوب بـ Django (المجلد `erp/`) إلى إضافة WordPress تعمل بـ PHP وMySQL، لتشغيلها على استضافة SiteGround المشتركة.

**البرنامج الأصلي هو المرجع.** أي اختلاف في رقم أو قيد عنه يُعتبر خطأ، إلا لو كان مذكوراً في قائمة الاختلافات المتفق عليها في `docs/PHASE1_REPORT.md`.

## المتطلبات

- WordPress 6.4 أو أحدث، **منفصل** على الدومين الفرعي `erp.metal-lines.com` (لا يُركّب على موقع metal-lines.com العام).
- PHP 8.1 أو أحدث، مع تفعيل امتداد **bcmath** (الإضافة ترفض التفعيل بدونه).
- MySQL أو MariaDB بمحرك InnoDB.

## التركيب

1. من SiteGround: Site Tools ← Domain ← Subdomains: أنشئ `erp.metal-lines.com`، ثم ركّب عليه WordPress جديد بقاعدة بيانات مستقلة.
2. Settings ← General: تأكد أن «Anyone can register» غير مفعّل (الإضافة تقفله تلقائياً).
3. Plugins ← Add New ← Upload: ارفع `erp-metal-lines.zip` وفعّلها. التفعيل ينشئ الجداول والصلاحيات.
4. افتح الموقع وسجّل دخولك بحساب المدير، ثم ادخل «إدارة النظام» واختر واحداً من الاتنين:
   - **تشغيل التهيئة** لبداية جديدة (شجرة الحسابات والضرائب والقيود الجاهزة).
   - **استرجاع** ملف نسخة احتياطية (من الإضافة أو من برنامج Django).
5. ركّب إضافة أمان موثوقة للتحقق بخطوتين (2FA) لحساب المدير، ولا تركّب أي إضافات أخرى.

بعد التفعيل يتحول الموقع كله لواجهة البرنامج بنفس روابط الأصل (`/journal/` و`/reports/trial-balance/` …)، ومفيش فيه أي صفحة عامة. أي زائر غير مسجّل بيتحوّل لصفحة الدخول، وواجهة REST مقفولة لغير المسجّلين، وXML-RPC مقفول تماماً.

## الصلاحيات

| الدور | الصلاحيات |
|---|---|
| مدير النظام المحاسبي (`erp_manager`) ومدير WordPress | كل شيء |
| محاسب (`erp_accountant`) | المستندات والقيود، والترحيل، والتقارير، والجهات |
| مدخل بيانات (`erp_data_entry`) | إنشاء المسودات والجهات فقط، بدون ترحيل |
| مراجع (`erp_viewer`) | عرض فقط |

تحديد دور كل مستخدم من: Users ← Edit ← Role.

## التحديث

1. نزّل نسخة احتياطية: الإعدادات ← تنزيل نسخة احتياطية.
2. ارفع نسخة الإضافة الجديدة واستبدل بيها القديمة.
3. أي تعديل في بنية الجداول بيتطبّق تلقائياً، عن طريق رقم إصدار الـ schema في `ERP_Schema::VERSION`.

## النسخ الاحتياطي والاسترجاع

- **تنزيل:** «إدارة النظام» ← «تنزيل نسخة احتياطية الآن». بينزل ملف JSON فيه كل جداول `erp_` بقيم نصية دقيقة.
- **استرجاع:** على قاعدة فارغة بس. امسح البيانات الأول لو موجودة، وبعدين ارفع الملف من «إدارة النظام». الاسترجاع بيتم كله في معاملة واحدة، ولو أي مرجع في الملف ناقص بيتلغي بالكامل.
- **يومياً:** فعّل Daily Backup من SiteGround (Site Tools ← Security ← Backups)، ونزّل نسخة JSON بشكل دوري.

## نقل البيانات من نسخة Django

من برنامج Django: الإعدادات ← «تنزيل نسخة احتياطية»، وارفع الملف ده في «إدارة النظام ← استرجاع». بتتنقل كل الجداول بنفس الأرقام التعريفية (ids). أما المستخدم اللي أنشأ كل مستند، فبيتربط بمستخدم WordPress اللي له نفس اسم الدخول لو موجود.

## للمطورين: الاختبارات

```bash
composer install
# قاعدة بيانات اختبار منفصلة (تُمسح مع كل تشغيل)
mysql -e "CREATE DATABASE wp_erp_tests; CREATE USER 'wp'@'localhost' IDENTIFIED BY 'wp'; GRANT ALL ON wp_erp_tests.* TO 'wp'@'localhost';"
vendor/bin/phpunit --testdox
```

الجداول والمسميات وشجرة الحسابات مولّدة من كود Django نفسه، بالأمر:
`python erp/tools/gen_php.py wp-plugin/erp-metal-lines/includes/generated`

والمجموعة المرجعية (Golden dataset) بتتصدّر من الأصل بالأمر:
`python manage.py export_golden <مجلد>`

## قواعد الدقة

- **ممنوع float.** كل الحسابات بـ bcmath عن طريق `ERP_Money`.
- **التقريب HALF_EVEN** (تقريب البنوك)، وده اللي بيستخدمه الأصل فعلاً عن طريق Python Decimal. التفقيط وحده HALF_UP، زي الأصل.
- **القسمة** بتتحسب بنفس دقة Python (28 رقماً معنوياً).
- **قبل الحفظ** كل قيمة عشرية بتتقرّب لعدد خانات العمود، زي ما Django بيعمل بالظبط.
